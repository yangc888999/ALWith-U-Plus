# ALWith U⁺ 指南

ALWith U⁺ 是基于 Codex CLI 的独立桌面客户端。你可以用它和 AI 助手协作、按项目整理会话，并在对话旁查看文件。本应用与 OpenAI 没有隶属或背书关系。

## 从这里开始

### 基本步骤
1. 打开 ALWith U⁺，登录 ALwith 账号。
2. 从侧边栏底部打开账户菜单，进入 **设置**，在服务商设置里配置 Codex 或其他模型。
3. 点击 **+** 新建会话；任务涉及本地文件时，先选择项目文件夹。
4. 在输入框选择模型，描述目标并发送。
5. 阅读回复、权限请求和文件改动后再继续。

ALwith 账号和模型访问是两件事。登录 ALwith 不会自动登录 Codex，也不会提供其他服务商的 API Key。ALWith U⁺ 与 ALwith Desktop 的 ALwith 登录会话相互独立。

可以先用一个具体任务验证环境：“读取这个项目的 README，说明如何启动它，不要修改文件。”如果要改代码，请同时说明预期结果和验证方式。

### 发送前检查

| 检查项 | 位置 | 期望状态 |
| --- | --- | --- |
| 账号 | 左下角账户菜单 | 已登录 ALwith 账号 |
| 模型 | 设置 → 服务商 | Codex 登录或其他服务商可用 |
| 项目 | 对话顶部和文件夹选择器 | 指向真正要处理的项目文件夹 |

先读后改。读取任务可以在不产生改动的情况下验证连接、模型和项目上下文。

### 一个可验证的小任务

在项目会话中发送：

> 读取 README 和 package 配置，说明这个项目做什么、用什么命令启动、有哪些检查可用。不要修改文件，并引用支持结论的文件。

收到回复后，在文件工作区打开它引用的文件进行对照。如果助手说运行过命令，展开活动记录查看真实输出。随后追问：

> 哪些步骤是你实际运行验证的？列出无法验证的部分并说明原因。

完成任务时，你应该能说清项目、当前模型、依据文件和“执行过的检查”与“只是建议”的区别。

## 熟悉界面

### 基本结构
左侧边栏用于切换插件、扩展和会话。聊天、活动、云盘等图标会切换侧边栏内容；账号有权限时才会出现云盘功能。

- **搜索：** 查找会话和可用命令。
- **窗口图标：** 打开独立聊天窗口。
- **+：** 新建会话。
- **项目分组：** 展开文件夹查看其中的会话。
- **侧边栏开关：** 固定或收起导航栏。
- **账户菜单：** 打开设置、手柄或退出登录。
- **帮助按钮：** 打开本指南；再次点击会把已有窗口带到前台。

指南随应用离线提供，不依赖外部文档网站。

### 从左到右阅读工作区

| 区域 | 用途 | 常见操作 |
| --- | --- | --- |
| 导航侧栏 | 选择会话或应用功能 | 展开项目并选择会话 |
| 对话区 | 描述任务、查看助手进度 | 阅读回复或展开工具活动 |
| 输入框 | 组织下一次请求并选择模型 | 添加上下文、选模型、发送 |
| 文件工作区 | 查看源码和产物 | 选择文件预览或编辑 |
| 底部状态区 | 查看云盘、版本等信息 | 排查传输问题或记录版本 |

指南首页的界面示意图只用于说明，不会在真实会话里执行任务。

### 切换上下文

选择会话会切换当前对话；新建会话会得到新的上下文。切换项目后，应先确认项目文件夹，再发起文件操作。

需要专注阅读时，可以收起侧边栏或调整文件区域；需要导航时再展开。独立聊天窗口适合把对话放在另一个应用旁边。

## 对话与检查

### 基本步骤
好的请求应包含目标、范围、约束和验证方式。只写“优化一下”通常会让助手猜测。

### 写出可执行的请求

建议包括：

- 要修改或查看的具体文件、目录或功能。
- 允许做什么、不允许做什么。
- 预期输出或验收标准。
- 希望实际运行的检查。

例如：

> 修复登录按钮在重复点击时发送两次请求的问题。只改认证相关代码，不调整视觉样式。补充回归测试，并运行相关测试和类型检查。

### 跟踪运行中的回合

运行时可看到工具活动、终端命令和进度。需要停止时点击停止按钮；需要补充方向时可直接发送补充说明。

如果出现权限请求，先确认命令、路径和访问范围，再决定允许一次或拒绝。不要在不清楚影响时批量放行。

### 检查结果再继续

查看助手声称修改的文件、实际输出和测试结果。对关键结论，打开源文件复核。若结果不完整，明确指出缺口并要求补查，而不是直接接受总结。

## 选择模型

### 基本步骤
先在设置 → 服务商中连接账号或填写 API Key，再在输入框底部选择模型。模型选择会跟随当前会话保存。

### 分步配置访问
1. 打开设置 → 服务商。
2. 选择 Codex、内置服务商或添加自定义服务商。
3. 完成登录或填写密钥。
4. 在模型列表中启用需要的模型。
5. 回到会话，在输入框底部确认模型名称和推理档位。

### 理解模型选择器

模型选择器按服务商分组。搜索、推理强度、快速模式和上下文能力可能因模型而异。切换会改变当前会话后续回合的路由。

同一模型名可能来自不同服务商，实际额度、路由和计费也不同。任务对稳定性和成本敏感时，先确认当前选择。

## 处理项目文件

### 基本步骤
项目会话可以同时查看对话、预览和文件树。开始改动前，确认项目目录，并优先阅读相关文件。

### 先看再改
1. 在文件树定位目标文件。
2. 阅读预览或编辑器中的内容。
3. 让助手解释关键逻辑和依赖。
4. 确认方案后再请求修改。

大项目应尽量指出具体文件或子目录，减少无关扫描，也更容易复核。

### 对话和文件一起用

保持回复与文件同时可见，先读解释，再对照源码。文档和产物保存后，与预览结果比较；不同格式的预览和编辑能力不同。

### 请求受控改动

> 在这个项目中修复指南按钮，让一次点击打开本地指南，同时保持账户菜单行为。检查重复点击和失败路径，最后报告改动文件和实际运行的检查。

## 插件与扩展

### 基本步骤
**插件** 管理 Codex 可用的技能与插件；技能提供可复用指令，插件可能附带工具和资源。**扩展** 管理 ALwith 应用扩展，可能增加界面入口或集成。

启用前阅读说明和所需权限。安装成功不等于每个会话都能使用，凭据、可用性和技能指令仍可能影响结果。

### 选择正确入口

| 入口 | 管理内容 | 检查重点 |
| --- | --- | --- |
| 插件 | Codex 技能与插件目录 | 指令、工具、安装状态和依赖 |
| 扩展 | ALwith 应用集成与界面入口 | 启用状态、配置和访问权限 |

### 验证新集成

1. 阅读说明和依赖。
2. 安装或启用。
3. 完成必要配置。
4. 用一个明确需要该能力的小任务测试。
5. 若入口未出现，检查启动诊断和错误。

## 云文件

### 基本步骤
云盘功能在账号和配置允许时出现。用云盘侧边栏和状态入口查看同步与传输失败。本地保存成功不等于已经上传成功。

如果同步失败，检查受影响项目、错误信息、网络和账号权限，再通过界面重试。处理期间保留本地副本。

### 核对一次完整传输

1. 保存本地改动。
2. 打开云盘状态查看当前传输。
3. 阅读失败项和错误。
4. 处理权限、网络或传输问题。
5. 确认远端结果后再分享或依赖该副本。

### 谨慎处理失败项

保留本地内容，确认失败范围是单个文件、资料库还是整个连接。处理原因后再重试；重复失败时记录文件和完整错误，不要上传敏感内容。

## 设置与快捷键

### 基本步骤
设置窗口集中管理账号、移动端连接、通用、主题、编辑器、语音、触控板、模型、云盘、扩展、自动化和关于信息。

修改快捷键前先确认冲突。按钮的悬停提示会显示可用快捷键；命令面板适合快速打开会话或功能。

### 建立舒适的工作区

按任务调整侧边栏、聊天、预览和文件栏宽度。常用项目可以固定，阅读长文时可以暂时收起导航。

### 记录版本信息

遇到问题时记录 ALWith U⁺ 版本、Codex 引擎版本、系统版本和发生时间。构建信息可在关于页和状态区查看。

## 故障排查

### 基本步骤
先描述现象，再按层排查：账号、模型服务商、网络、项目目录、文件权限、扩展。每次只改一个变量，并记录结果。

### 使用可重复的排查顺序

1. 用最小任务复现问题。
2. 记录完整错误和发生时间。
3. 检查账号和模型连接。
4. 确认项目目录可读写。
5. 暂时禁用可疑扩展或技能。
6. 重启应用后再次验证。

### 分层判断

连接失败通常是账号、网络或服务商问题；模型不可用可能是目录、密钥或路由问题；文件失败则检查路径、权限和格式。不要把不同层的错误混在一起。

附带日志时先移除密钥、Cookie、个人信息和敏感文件内容。
